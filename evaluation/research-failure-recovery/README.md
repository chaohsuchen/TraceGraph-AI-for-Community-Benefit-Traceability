## 同一份 H001 响应

公开原问题经旧版搜索指令发起一次工具上限为 4 的搜索。返回的一份回复包括 completed search、两次 completed open_page、completed find_in_page，以及一个 searching 动作。模型在同一回复已给出 9 个引文提议。

| 处理步骤 | 原版 | 修复版 |
|---|---:|---:|
| 保留下来的可归属于已完成动作的 URL | 抛错 | 21 |
| 通过公开文档逐字校验的引文 | 0 | 3 |
| 两版回放期间的额外模型调用 | 0 | 0 |

公开文档读取和校验发生在修复后的真实来源读取器中。程序保留已核验引文的来源和文本散列，以及当次成功读取文档的 SHA-256。通过校验的引文不代表履约的证明，不能直接计为 3 个 Golden 命中。[同一份搜索回复](TG-GOLD-H001-paired-response.json) · [公开文档核对结果](H001-paired-result.json)

## 修复行为与测试

- 多个动作的终态不同，程序仅采纳已完成动作中明确出现的来源。没有动作归属的消息注释不能引入新的 URL。每个候选摘录仍要能在实际网页或 PDF 中逐字定位。
- 如果整份响应没有可归属的已完成来源，首次 discovery 可自动使用剩余预算重试一次。测试覆盖先请求 4 个、再申请 2 个的路径，第二次仍失败就结束。权限错误和拒答不触发此重试。
- 可选补查失败会保留之前逐字核验的资料。已判断与原问题相关的摘录出现在 `facts`；归属尚未确认的材料单列为 `unmatched_records`。回归从 Agent 入口确认五条已捕获记录都能返回，示例中四条已归属、一条待归属，没有创建承诺或给出履约判定。
- 全部 **191 个 Python 测试通过**，含使用本地 PostgreSQL 临时 schema 的集成测试和五个新增回归。没有调用模型为修复后的 22 条重新评分。
